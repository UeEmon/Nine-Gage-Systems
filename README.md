# SenroLab（センロラボ）

SenroLab ではペーパークラフトの展開図作成は行いません。

旧称 Nine-Gage。リポジトリ名や環境変数（`NINEGAGE_*`）は互換のため旧名のまま。

AIと一緒にNゲージ鉄道模型の線路レイアウトを設計するWebアプリです。

SenroLab は2つの機能でできています。レイアウトを作って管理する中核の機能を**プラットフォーム**（このリポジトリのルート）、ユーザー間でレイアウトを共有する機能を**ターミナル**（`terminal/`）と呼びます。ターミナルは 2026-11-24 に「みんなのレイアウト」（`share/`）から改名しました。旧URL（`/share`）は `/terminal` へ転送し、旧名の環境変数（`SENROLAB_SHARE_*`・`SHARE_*`）と旧データファイル（`share.sqlite`）もしばらく受け付けます。

## できること

- **メーカー選択**: KATO（ユニトラック）と TOMIX（ファイントラック）から選べます。パレット・AIの提案・部品リストがそのメーカーの線路になります。
- **線路エディタ**: 直線・曲線・ポイント・車止めを、選んだ端（赤い丸）につないでいきます。ドラッグで移動すると近くの端に吸着します。回転・左右反転・削除（キー: `R` / `F` / `Delete`）。
- **ボード設定**: 900×600、サブロク（1820×910）などのプリセットか任意のサイズ。はみ出した線路は赤く表示されます。
- **AIレイアウト提案**: 要望を日本語で書くと、AIが線路部品の並びを提案します。アプリ側で組み立てて「つながっていない端・ずれ・ボード外・重なり」を検査し、問題があればAIに直させます（最大4回）。
- **ログインとロール**: 「管理者」「プレミアムユーザー」「一般」の3つのロールと、ログインなしでの利用があります。だれでもユーザー登録でき（一般）、一般ユーザーは自分のAPIキーを設定してAI提案を使えます。ログインなしでもエディタは使えます（AI提案なし）。詳しくは下の「ログインとロール」。
- **AIの切り替え**: Claude・OpenAI・Gemini・ローカルLLM（Ollama / LM Studio / vLLM など OpenAI 互換API）から選べます。管理者が「管理」画面でプロバイダ・モデル・APIキー・接続先URLを設定し（環境変数でも可）、全員のAI提案にその設定が使われます。「一覧」ボタンで使えるモデルを取得できます。
- **新機能のお知らせ**: 画面右上のベル（🔔）に、新しい機能や管理者からのお知らせが未読数付きで届きます。開くと既読になり、「すべてのお知らせ」（`/news`）で更新履歴を見られます。
- **高架・立体交差と階層表示**: 線路ごとに高さ（地上・高架・地下・勾配）を設定できます。地下はマイナスの高さで、図では薄い破線、運転席の映像では掘割とトンネルで表します。勾配は前後の高さから自動で上り下りし、急勾配・段差・高さ不足の交差・下の線路に当たる橋脚を検査します。キャンバス左上で地上・勾配・高架・地下の強調／非表示を切り替え、「断面図」で高さを横から確認できます。詳しくは下の「高架・立体交差」。
- **運転席で走る（一人称視点）**: キャンバス左上の「▶ 運転席で走る」で、作ったレイアウトの線路の上を運転席の視点で走る3Dの映像を見られます（three.js）。曲線・勾配・高架・橋脚・地下（掘割・トンネル・坑口）と、道床の種類（バラスト・PC・スラブ・ワイドPC・高架橋）を反映します。選択中の部品から走り始め、「後ろから」では1/150の20m級の車両（133mm）3両が台車の位置で線路に沿って走ります。速度（縮尺の km/h）・一時停止・ポイントの進路（直進・分岐・交互・おまかせ、次のポイントだけ選ぶことも可）・運転席／後ろからの視点を切り替えられます。行き止まりでは手前で止まり、折り返せます。「録画」で、ブラウザが対応する WebM・MP4 と画質を選んで保存できます。直前の録画は、走行画面を開いている間に別の形式・画質へ再エンコードできます。走行の計算は `src/lib/drive.ts`、3Dの情景は `src/lib/driveScene.ts`。
- **線路以外のパーツ**: 踏切・信号機・駅のホーム（島式・対向式）・橋上駅舎・跨線橋・駅舎・建物を、KATO・TOMIXの実製品（品番・価格つき）として置けます。詳しくは下の「線路以外のパーツ」。
- **確認結果と部品リスト**: 必要な線路を**メーカー品番**ごとに本数・箱数で表示します（ポイントは左右別）。線路延長も表示します。
- **運行計画**：運行計画の「計画を保存」「計画を読み込む」で、駅名・列車・停車駅の設定をJSONに書き出し、同じレイアウトのダイヤを切り替えられます。
- **保存**: ブラウザに自動保存。JSONファイルで保存・読み込みもできます。
- **改善リクエスト**: ログインした人は画面右上の「改善リクエスト」から、要望・不具合を送れます。送った内容は GitHub の Issue になります。詳しくは下の「改善リクエスト」。
- **ターミナル（レイアウトの共有）**: 作ったレイアウトを投稿・共有し、投稿どうしをボードの端の線路でつないで大きなレイアウトにできる、別コンテナのサイトです。SenroLab のアカウントでログインします。詳しくは [terminal/README.md](terminal/README.md)。

## 仮オブジェクトの編集・3Dモデルの配置

右側の「仮オブジェクト・3Dモデル」で、仮オブジェクトの名前・種類・内容、X/Y/Z・回転・長さ・幅・高さを変更できます。数値は入力欄を離れると反映されます。X/Y はボード左上から右・下へ、Z は地上のレール面からの高さで、単位は mm です。

「3Dモデルを追加」から STL（バイナリ・ASCII、256KB以下、20,000面以下、立体形状）を読み込めます。STL の Z 軸を高さとして扱い、最長辺100mmに縮尺を合わせてボード中央に配置します。配置後は各寸法を変更できます。平面図は配置枠と名前、運転映像はモデルの形状を表示します。色・テクスチャは取り込まず、単色で表示します。

モデルはレイアウトの保存データに含まれ、JSON書き出し・読み込みでも維持されます。モデルの合計は1レイアウト約1MBまでです。ブラウザの保存容量には上限があるため、JSONファイルにも書き出してください。GLB・OBJ には未対応です。

### 品番データベース

`src/lib/productDb.ts` が、カタログと価格表から品番ごとの1行（メーカー・品番・製品名・分類・左右・入数・中身の部品と本数・寸法・確認状況・価格・出典）を作ります。

- `GET /api/products` … JSON
- `GET /api/products?format=csv` … CSV（Excelで開けるようBOM付き）

端数線路セットやミニカーブのように、1箱に複数の部品が入っている品番は「中身」に部品ごとの本数を持ちます。

## 高架・立体交差

- 高さは「地上の線路のレール面からの高さ（mm）」です。標準の高架は KATO 50mm（橋脚No.5）、TOMIX 55mm（PC橋脚P10）。規格と出典は `src/data/piers.ts`。
- 「線路パーツ」の「置く高さ」で高架・地下や任意の高さを選べます。「ボード上で配置位置を選ぶ」をオンにすると、線路パーツを選んでから盤面をクリックした場所に配置できます。
- 「勾配」にした線路は、つながった勾配の線路をひとつの坂として、前後の高さの決まった線路の間を長さに比例して上り下りします（`src/lib/elevation.ts`）。勾配の上限は4%（KATOは248mmで10mm、TOMIXはS140で5mmが目安）。
- 高さの差が標準の高架の高さ（KATO 50mm・TOMIX 55mm）以上ある交差は立体交差、足りなければ「重なり（高さ不足）」になります。
- 高さ8mm以上の線路には、ジョイントごと（と長い線路の途中）に橋脚を立て、高さに合う橋脚を選んで部品リストに加えます。勾配橋脚セットのように1箱に何種類も入っている品番は、ほかの高さの不足分にも充てて箱数を数えます。
- TOMIXの鉄橋はレールが別売りなので、同じ長さのレール（S280・S140）も部品リストに入ります。鉄橋に付属する橋脚は数えていません。
- AIには高さ（`height`。0=地上、null=勾配）も出力させ、急勾配・段差・高さ不足・橋脚の干渉をフィードバックして直させます。

## 線路以外のパーツ

- 品番・製品名・メーカー希望小売価格・寸法は `src/data/accessories.ts`（各社公式サイトの掲載値、2026-11-15 取得）。公式に載っていない寸法（ホームの幅、TOMIXの建物の大きさなど）は推定で、`geometryNote` に「推定」と書いています。
- 置き方は4種類です。踏切・信号機は線路の上（onTrack）、ホームは線路の横（beside。対向式は線路の中心からホームの中心まで「11mm＋幅の半分」、島式は両側の線路の間隔のまんなか）、橋上駅舎・跨線橋は線路をまたぐ（over）、駅舎・建物はどこにでも（free）。ドラッグすると60mm以内の線路に吸着し、置いた線路の高さ（高架）に合わせます（`src/lib/accessories.ts`）。
- 配置は `Layout.accessories` に線路とは別に保存し、パターンのファイルにも入ります。
- 部品リスト・所有パーツ・不足分の計算では1個ずつ数えます（在庫キーは `kato:acc:20-652` のような形）。KATOの自動踏切（踏切線路124mm付き）・自動信号機（64mm）、TOMIXのTCS信号機（S70）は、その長さの直線の上に置くと、その線路を数えません。
- AIには `accessories`（パーツID・置く区間と部品・左右）を出力させ、指定した部品のまんなかに置きます。

## 所有パーツからの提案と拡張案

1. 左の「所有パーツ」で品番と箱数を登録します（このブラウザに保存。「今の配置から追加」で配置済みの線路をまとめて登録することもできます）。
2. 右のAI欄でモードを選びます。
   - **自由に** … 部品の制限なし
   - **手持ちだけ** … 所有パーツの本数の範囲で組める案。使いすぎた案はアプリが「部品不足」としてAIに直させます
   - **拡張案** … 所有パーツを活かし、買い足しで広げる案。案ごとに追加で必要な品番・本数・箱数・費用を表示します
3. 「出す案の数」で1〜3案を同時に作れます（案ごとに方向を変えます。拡張案なら小・中・大の規模）。
4. 「自由に」と「拡張案」では、任意で**予算の上限**（円）を入れられます。追加で買う部品の合計（メーカー希望小売価格・税込、箱単位）が上限以内の案だけを出します。所有パーツの分は費用に数えません。AIには部品1本あたりの価格を渡し、上限を超えた案は「予算超過」として直させます。直しても収まらなかった案は出さず、理由を表示します。空欄なら従来どおり制限なしです。
5. 部品リストには所有パーツとの差分（不足本数）と価格も出ます。

## パターンの編集・保存

- 提案された案は「表示して編集」でキャンバスに出し、自由に編集できます。「登録」でアプリ内に保存。
- 「パターンの保存」欄で、新しく登録・上書き保存・名前変更・削除ができます（このブラウザに保存）。
- 1件ずつ、または全パターンをまとめてJSONファイルに出力でき、そのファイル（以前の「JSONで保存」で作ったファイルも）を読み込めます。
- 部品の形は `src/lib/shapes.ts` の「経路（直線と円弧の並び）」で表すので、ジョイントが3つ以上の部品（3方・交差・ダブルクロス・複線）も同じ仕組みで配置・接続判定できます。

## 改善リクエスト

- ログインした人が `/feedback`（画面右上の「改善リクエスト」）から、種類（機能の追加・改善／不具合の報告／その他）・機能区分・件名・内容を送ります。1人あたり1時間に5件、1日に20件まで。
- サーバーにまず保存し（`store.sqlite`）、`NINEGAGE_FEEDBACK_GITHUB_TOKEN` があれば `NINEGAGE_FEEDBACK_GITHUB_REPO`（既定 `UeEmon/Nine-Gage-Systems`）に Issue を作ります。ラベルは `改善リクエスト` と、種類に合わせて `enhancement` か `bug`。機能区分は本文の最初に `feature:…` の形で書くので、Issue 用のワークフロー（`.github/workflows/feature-triage.yml`）が機能のラベルと担当者を付けます。
- リポジトリは公開なので、Issue にはユーザー名・メールアドレス・ユーザーIDを載せず、受付番号（IDの先頭8文字）だけを書きます。本文のメールアドレスは伏せ、`@ユーザー名` はメンションにならないようにします。だれが送ったかは管理画面の「改善リクエスト」でだけ見られます。
- トークンが未設定・GitHub に届かなかったときも受け付けたものは残り、管理画面に理由が出ます。「Issue にする」で登録し直せます。
- トークンは fine-grained personal access token で、「Repository access」を対象のリポジトリだけ、「Permissions」を Issues: Read and write だけにします。Issue はトークンの持ち主のアカウントで作られます。

## 仕組み

AIに座標を直接計算させるとずれが出やすいため、AIには「どの部品をどの順につなぐか」だけを構造化出力（JSON）で出させ、座標はアプリが計算します。

```
要望 ──▶ AI (Claude / OpenAI / Gemini / ローカルLLM, 構造化出力) ──▶ 部品の並び
                ▲                                 │
                └── 問題点のフィードバック ◀── 幾何計算・検査 (src/lib/plan.ts, geometry.ts)
```

| ファイル | 役割 |
|---|---|
| `src/data/trackCatalog.ts` | KATO・TOMIXの品番・寸法（公式サイトから抽出） |
| `src/lib/shapes.ts` | 部品の形（直線・円弧の経路）と、そこから求めるジョイント |
| `src/lib/parts.ts` | カタログから部品定義を生成 |
| `src/lib/bom.ts` | 品番ごとの必要本数・箱数の集計 |
| `src/lib/geometry.ts` | 配置計算、接続判定、はみ出し・重なり・立体交差・段差・勾配の検査、部品集計 |
| `src/lib/elevation.ts` | 高さ（勾配の自動計算）と橋脚の配置 |
| `src/data/piers.ts` | 高架の高さ・勾配の規格と橋脚の品番 |
| `src/lib/plan.ts` | AIの出力スキーマと、部品の並び → 配置への変換 |
| `src/lib/ai.ts` | システムプロンプトと、検証・再試行ループ（プロバイダ共通） |
| `src/lib/llm/` | プロバイダごとの呼び出し（`anthropic.ts` / `openai.ts`（ローカルLLMも） / `gemini.ts`）と設定の解決 |
| `src/lib/server/` | ユーザー・AI設定・お知らせの保存（`store.ts`）、パスワード、ログイン状態、ロールの確認（`auth.ts`）、ユーザー管理、お知らせ（`notices.ts`） |
| `src/data/releases.ts` | リリースノート（新機能のお知らせ。デプロイで自動的に出る） |

## 開発

```bash
npm install
cp .env.example .env.local   # NINEGAGE_ADMIN_PASSWORD（最初の管理者）を設定。AIのキーは管理画面でも入れられる
npm run dev                  # http://localhost:3000
npm test                     # ジオメトリとAIループのテスト

```

### 共同開発の流れ

1. ブランチで作業し、main へのPRを出します（main へは直接 push できません）。
2. CI（`.github/workflows/ci.yml`）がテスト・型チェック・`npm audit`（本番の依存に high 以上がないこと）・イメージのビルドと脆弱性検査を行います。
3. 承認されてマージすると、CI が `ghcr.io/ueemon/nine-gage-systems:main` を作り、数分でステージング（`https://nine-gage-staging.<ドメイン>`、パスワードは所有者から）に出ます。
4. 本番に出すのは所有者がタグ `v1.2.3` を付けたときだけです（`:stable` が動き、本番が取り込む）。

### 機能ごとの担当

ソースは機能（線路エディタ・線路カタログ・高架・パーツ・部品リスト・運転席視点・運行計画・AI提案・アカウント・管理画面・お知らせ・基盤）に分け、機能ごとに担当者を決めています。一覧と各機能のファイルは [docs/FEATURES.md](docs/FEATURES.md)。

- 担当は `.github/features.json` の `owners` で決め、`npm run features` で `CODEOWNERS`・PRの自動ラベル・Issueテンプレート・機能一覧を作り直します。
- PR には変更したファイルの機能の `feature:…` ラベルが自動で付き、その機能の担当者の承認が要ります。Issue はテンプレートで機能区分を選ぶと担当者が割り当てられます。
- 機能の担当の承認とは別に、すべての PR は統括管理責任者（`.github/features.json` の `supervisor`）が最新のコミットを承認しないとマージできません（チェック「最終承認」）。
- サーバー側のコード、API、依存、Dockerfile、CI は保護する場所として、機能の担当ではなく所有者の承認が要ります。
- 新しいファイルがどの機能にも入っていないと `npm test` が失敗します。

依存とベースイメージの更新は Dependabot が週に一度PRを出します。

## トップページとアドレス

本番では、同じアプリが2つのアドレスで動きます（振り分けは `src/proxy.ts` と `src/lib/sites.ts`）。

| アドレス | 環境変数 | 出すもの |
|---|---|---|
| トップページ（例 `https://www.senrolab.com`） | `NINEGAGE_HOME_URL` | `/` にトップページ（中身は `src/app/home/page.tsx`）、ログイン・ユーザー登録・メールの確認・パスワードの再設定・アカウント・APIキーのチュートリアル。ほかのパスはプラットフォームへ転送 |
| プラットフォーム（例 `https://platform.senrolab.com`） | `NINEGAGE_PUBLIC_URL` | エディタ・管理・改善リクエスト・お知らせなど。ログインまわりのパスはトップページへ転送し、ログインのあとはもとの画面へ戻る（`?next=`） |

- 2つのアドレスでログインを共有するため、`NINEGAGE_COOKIE_DOMAIN`（例 `senrolab.com`）でログインの Cookie をそのドメイン全体のものにします。ログアウトでは、共有の Cookie と以前のそのアドレスだけの Cookie の両方を消します。同じ名前の Cookie が複数届いたとき（ステージングなど）は、有効なものを使います。
- `/editor` はどちらのアドレスからでもプラットフォームのトップへ移ります。画面の「プラットフォームへ」のリンクに使います。
- `NINEGAGE_HOME_URL` がない（または `NINEGAGE_PUBLIC_URL` と同じ）ときは、これまでどおり1つのアドレスで全部を出します（開発・ステージング）。トップページは `/home` で確かめられます。
- メールのリンク（登録の確認・パスワードの再設定）は、トップページのアドレスで作ります。

## ログインとロール

| ロール | AI提案 | できること |
|---|---|---|
| 管理者 | サーバーのAPIキー（管理者の設定） | 「管理」画面でAIの設定（プロバイダ・モデル・APIキー・接続先URL）、ユーザー管理（追加・ロール変更・パスワード再設定・削除）、お知らせ、AIの使用量と料金 |
| プレミアムプラス | サーバーのAPIキー（プレミアム用の設定）。管理者が決めた月の上限まで | 管理者が一般ユーザーの中から選び、月の上限（円）を1人ずつ決める（空欄なら上限なし）。上限に達したら、登録した自分のAPIキーで続けられる |
| プレミアムユーザー | サーバーのAPIキー（プレミアム用の設定）。支援額に応じた上限まで | GitHub Sponsors で支援し、「アカウント」画面で GitHub を連携した一般ユーザー（保存はしない。支援が有効なあいだだけ）。上限に達したら、登録した自分のAPIキーで続けられる |
| 一般 | 自分で設定したAPIキー | だれでも登録できる（メールアドレスの確認つき）。レイアウトの作成・自分のパスワード変更。「アカウント」画面で自分のAPIキー（Claude・OpenAI・Gemini）とモデルを設定すると、AI提案を使える |
| ログインなし | 使えない | レイアウトの作成・部品リスト・運転席の映像。保存はこのブラウザとファイルの書き出し・読み込みだけ |

- ユーザー登録（`/signup`）はだれでもでき、ユーザー名・メールアドレス・パスワードを入れると確認メールが届きます。メールのリンク（`/verify#トークン`、24時間有効）を開いて「登録を完了する」を押すと「一般」になり、ログインします。確認が済むまではログインできません。期限が切れた登録は次の登録のときに消え、同じメールアドレスで確認待ちの登録があれば作り直します。確認済みのアドレスで登録しようとしたときは、画面には同じ表示を出し、本人にだけ「登録済みです」とメールで知らせます。
- パスワードを忘れたときは、ログイン画面の「パスワードを忘れた方」（`/forgot`）で登録したメールアドレスを入れると、再設定のリンク（`/reset#トークン`、60分有効、1回だけ）が届きます。新しいパスワードにするとそのままログインし、ほかの端末のログインは切れます。登録のないアドレスでも画面には同じ表示を出します（登録の有無を漏らさない）。同じ送信元・同じメールアドレスで1時間に5回まで。メールアドレスのない（管理者が追加した）ユーザーは、管理者が再設定します。パスワードの変更・管理者による再設定で、送ったリンクは無効になります。
- メールは `NINEGAGE_SMTP_URL` と `NINEGAGE_MAIL_FROM` で送ります。本番は OCI Email Delivery（`smtp://<SMTPユーザー名>:<SMTPパスワード>@smtp.email.ap-tokyo-1.oci.oraclecloud.com:587`、ユーザー名とパスワードはURLエンコード、差出人は承認済み送信者）。Gmail なら `smtps://you%40gmail.com:アプリパスワード@smtp.gmail.com:465`。`smtp://` では STARTTLS を必ず使います（`localhost` を除く）。リンクの基点は `NINEGAGE_HOME_URL`（なければ `NINEGAGE_PUBLIC_URL`）。本番でこれらが未設定なら登録を受け付けません。開発中（`npm run dev`）はメールを送らず、サーバーのログに本文を出します。
- ログインはユーザー名かメールアドレスでできます。
- 同じ送信元・同じメールアドレスからの登録は1時間に5件まで。`NINEGAGE_SIGNUP=closed` で登録を止められます（管理者の追加だけになる）。
- 「プレミアムプラス」は、管理者が一般ユーザーの中からロールを変えて選びます。管理者がユーザーを追加するときは「一般」か「管理者」だけを選べ、メールの確認が済んでいない人はプレミアムプラスにできません。
- 以前の「プレミアムユーザー」（管理者が選んだ人）は、そのまま使えるよう上限なしの「プレミアムプラス」として読み込みます（保存形式の版3）。

### GitHub Sponsors とAIの月の上限

- 一般ユーザーが「アカウント」画面の「GitHub と連携」で GitHub のアカウントを結び付け、そのアカウントが `NINEGAGE_SPONSORS_LOGIN`（既定 `UeEmon`）を支援していれば、プレミアムユーザーとして扱います。毎月の支援は続いているあいだ、1回きりの支援は支援した日から決めた日数（既定30日）のあいだ有効です。同じ GitHub アカウントは1人にしか連携できません。
- 月の上限（円）は「支援額（米ドル）× 円換算のレート × 倍率（既定0.75）」。倍率と日数は管理画面の「GitHub Sponsors とプレミアムユーザー」で変えられます。プレミアムプラスの上限はユーザー管理で1人ずつ決めます。
- 使った分は、AIの使用記録（`ai-usage.jsonl`）のうちサーバーのキーで使った料金を円換算して数えます。毎月の支援とプレミアムプラスは日本時間の毎月1日に戻り、1回きりの支援はその支援の日から数えます。上限はAIを呼ぶ前に確かめるので、最後の1回で少し超えることがあります。単価の分からないモデルの分は数えません。
- 上限に達したら、自分のAPIキーを登録している人はそのキーに切り替え、ない人には上限に達したことと戻る日を出して止めます。
- 設定（環境変数）:
  - `NINEGAGE_GITHUB_CLIENT_ID` / `NINEGAGE_GITHUB_CLIENT_SECRET`: GitHub の OAuth App（Settings → Developer settings → OAuth Apps）。Authorization callback URL は `<NINEGAGE_HOME_URL>/api/account/github/callback`。連携のときに、その人のトークン（`read:user`）で支援を1回だけ読みます（トークンは保存しない）。
  - `NINEGAGE_SPONSORS_WEBHOOK_SECRET`: GitHub Sponsors のダッシュボード（Webhooks）に `<NINEGAGE_HOME_URL>/api/sponsors/webhook`（Content type は `application/json`）を登録したときの Secret。支援の開始・額の変更・終了を受け取ります。
  - `NINEGAGE_SPONSORS_TOKEN`（任意）: 支援先のアカウントの classic personal access token（`read:user`・`read:org`）。管理画面の「GitHub から読み直す」で、全員の支援を読み直します（Webhook を取りこぼしたときや、Webhook を登録する前からの支援）。
- 一般ユーザーのAPIキーは AES-256-GCM で暗号化して保存し、画面には末尾4文字しか出しません。鍵は `NINEGAGE_SECRET_KEY`（32文字以上の乱数を推奨）。未設定なら `NINEGAGE_DATA_DIR/secret.key`（権限600）を作って使います。あとから `NINEGAGE_SECRET_KEY` を設定しても、それまでのキーはファイルの鍵で読めます。鍵を失うと保存済みのキーは読めなくなり、各ユーザーに入れ直してもらう表示が出ます。
- 一般ユーザーのAIは接続先URLを指定できず（ローカルLLMも選べない）、サーバーの環境変数のキーや接続先も使いません。
- 自分のキーで使った分は使用記録に `keySource: "own"` として残し、管理画面の「AIの使用量と料金」ではサーバーの料金と分けて「自分のAPIキーでの利用」に出します。
- 以前の版の「一般」ユーザー（サーバーのAIを使えていた人）は、そのまま使えるよう「プレミアムユーザー」として読み込みます。
- 最初の管理者は、ユーザーが1人もいないときだけ `NINEGAGE_ADMIN_USER` と `NINEGAGE_ADMIN_PASSWORD`（10文字以上）から作られます。
- ユーザーとAI設定は `NINEGAGE_DATA_DIR`（既定 `./data`、Docker では `/data`）の `store.sqlite`（SQLite、権限600）に保存します。以前の版の `store.json` があれば、最初に起動したときに取り込み、`store.json.migrated` に名前を変えます（確かめたら消してかまいません）。パスワードは scrypt のハッシュです。管理者が設定したAPIキーも、一般ユーザーのキーと同じ鍵で暗号化して保存します（以前の版で平文のまま保存したキーは、起動後に最初に読んだときに暗号化して書き直します）。
- ログイン状態は署名付きの Cookie（HttpOnly、SameSite=Lax、本番は Secure）で14日間です。パスワードの変更・再設定やロールの変更で、そのユーザーのほかのログインは切れます。
- 管理者が1人もいなくなる変更（最後の管理者のロールを変える・削除する）と、自分自身の削除はできません。
- ログインの失敗は、同じ送信元またはユーザー名で15分に10回までです。
- 書き換えの要求は、同じサイトの画面からだけ受け付けます（Origin を確認）。
- `http://` で試すときは `NINEGAGE_INSECURE_COOKIE=true`（`npm run dev` では不要）。
- API: `POST /api/auth/signup`（確認メールを送る）、`POST /api/auth/verify`（`{"token"}`で登録を完了）、`POST /api/auth/forgot`（`{"email"}`で再設定のメールを送る）、`POST /api/auth/reset`（`{"token","password"}`で新しいパスワードにする）、`GET/PUT /api/account/ai`（一般ユーザーの自分のAI。`apiKey` は省略で据え置き、空文字で削除）

## AIの設定

| プロバイダ | APIキー | モデル（既定） | 接続先URL |
|---|---|---|---|
| Claude | `ANTHROPIC_API_KEY` | `ANTHROPIC_MODEL`（claude-opus-5-5） | — |
| OpenAI | `OPENAI_API_KEY` | `OPENAI_MODEL`（gpt-5） | `OPENAI_BASE_URL`（任意） |
| Gemini | `GEMINI_API_KEY` | `GEMINI_MODEL`（gemini-2.5-pro） | — |
| ローカルLLM | `LOCAL_LLM_API_KEY`（任意） | `LOCAL_LLM_MODEL`（llama3.1） | `LOCAL_LLM_BASE_URL`（http://localhost:11434/v1） |

- 管理画面の設定が環境変数より優先されます。空欄の項目は環境変数を使います。キーは管理画面にも末尾4文字しか表示しません。
- 構造化出力（JSON Schema）に対応していないローカルLLMでは、自動で「JSONだけを出力」する指示に切り替えます。小さなモデルだと線路がうまく閉じないことがあるので、14B以上を目安にしてください。
- ローカルLLMのURLは、このアプリの**サーバーから見た**アドレスです。クラウドに置いた場合、手元PCのOllamaにはそのままでは届きません。
- 接続先URLを変えられるのは管理者だけです。プレミアムユーザー・一般ユーザーの画面からは、管理者の設定のキーもURLも送れません（一般ユーザーが送れるのは自分のAPIキーだけ）。

### トークンの節約（キャッシュ）

- **プロンプトキャッシュ（Claude）**: システムプロンプト（部品カタログ・例・設計のコツ。メーカーごとに固定）にキャッシュの目印を付け、さらにリクエスト全体の自動キャッシュで、検査の指摘を受けて出し直すときにそれまでの会話を再利用します。ボード・要望・所有パーツ・予算はユーザーメッセージに入れ、システムプロンプトには入れません（入れるとキャッシュが効かなくなります）。
- 複数案を頼んだときは、1つ目の応答が始まってから（＝キャッシュが書き込まれてから）2つ目以降を送ります。同時に送るとどれもキャッシュを読めないためです。
- `ANTHROPIC_CACHE_TTL=1h` にすると、システムプロンプトのキャッシュを1時間保持します（書き込みは5分の2倍の料金）。利用が5分以上あくことが多いサーバー向けです。既定は5分。
- OpenAI と Gemini は各社の自動キャッシュに任せ、読んだ量だけを集計します。
- **AIで作ったレイアウトの自動保存と再利用**: AI提案の案は、できるたびにユーザーごとに `store.sqlite` の `ai_layouts` に保存します（1人100件まで、超えたら古いものから消す。再起動しても消えず、バックアップにも入ります）。画面の「AIで作ったレイアウト」から開き直す・パターンに登録する・削除するができます。同じ人が同じ条件（AIのプロバイダとモデル・ボード・要望・メーカー・モード・所有パーツ・予算・再現の対象と再現度・案の方向）で頼んだときは、AIを呼ばずに保存済みの案を返します。アプリの更新でAIへの指示が変わっても保存済みを使うので、作り直したいときは画面の「新しく作り直す」を押します。
  - API: `GET /api/ai-layouts`（自分の一覧）、`GET /api/ai-layouts/{id}`（1件の中身）、`DELETE /api/ai-layouts/{id}`
- 管理画面の「AIの使用量と料金」と、サーバーログの `[ai-usage]` の行で、入力・キャッシュ読込・キャッシュ書込・出力のトークン数と料金を確認できます。

### 使用量と料金の記録

- 提案した案ごとに1件、`NINEGAGE_DATA_DIR/ai-usage.jsonl` に追記します（日時・ユーザー・機能（自由／所有パーツ／拡張案）・モデル・トークン・料金）。再起動しても残ります。
- 料金は記録したときの単価で計算して保存します。単価は `src/lib/llm/pricing.ts`（Claude の公表価格、2026年11月時点）。キャッシュ書込は入力単価の1.25倍（5分）・2倍（1時間）、読込は各モデルの読込単価です。
- Claude 以外のモデルや価格の変更は `AI_PRICING_JSON` で上書き・追加できます（例 `{"gpt-5":{"input":1.25,"output":10,"cacheRead":0.125}}`、単位は米ドル／100万トークン）。単価が分からないモデルは料金に入れず、管理画面に表示します。
- 円換算のレートは管理画面で設定します（既定 1ドル=150円、サーバーに保存）。
- API: `GET /api/admin/ai-usage?period=this-month|last-month|30d|all`、`PUT`（`{"usdJpy":150}`）

## デプロイ

`output: "standalone"` でビルドするので、Docker でそのまま動きます。

```bash
docker build -t nine-gage .
docker run -p 3000:3000 -v nine-gage-data:/data --env-file .env.local nine-gage
```

`GET /api/health` は `{"ok":true}` を返し、イメージの `HEALTHCHECK` と外部の死活確認に使います。リポジトリの変数 `NINEGAGE_HEALTH_URL` を設定すると、`.github/workflows/uptime.yml` が15分ごとに外から確かめ、応答がなければ GitHub から所有者にメールが届きます。

### バックアップと復元

```bash
# 書き出し（実行中のコンテナから。一貫した写しを AES-256-GCM で暗号化して標準出力へ）
docker compose exec -T nine-gage node scripts/backup.mjs > ninegage.ngbak
# 復元（同じ NINEGAGE_BACKUP_KEY で。中身を検査してから新しいファイルに書く）
NINEGAGE_BACKUP_KEY=... node scripts/restore-backup.mjs ninegage.ngbak store.sqlite
```

鍵は `NINEGAGE_BACKUP_KEY`（32文字以上）。バックアップの中のAPIキーは別の鍵 `NINEGAGE_SECRET_KEY` で暗号化されているので、復元先でも同じ `NINEGAGE_SECRET_KEY` が要ります。どちらの鍵もサーバーの外（所有者の手元）に控えておきます。公開中の構成（Oracle Cloud の VM、Caddy、ネットワークの分離、ステージング）は [UeEmon/oracle-cloud-deploy](https://github.com/UeEmon/oracle-cloud-deploy) にあります。

AI提案は1回に1〜3分かかることがあるため、リバースプロキシのタイムアウトは300秒程度にしてください。

# Nine-Gage-Systems

AIと一緒にNゲージ鉄道模型の線路レイアウトを設計するWebアプリです。

## できること

- **メーカー選択**: KATO（ユニトラック）と TOMIX（ファイントラック）から選べます。パレット・AIの提案・部品リストがそのメーカーの線路になります。
- **線路エディタ**: 直線・曲線・ポイント・車止めを、選んだ端（赤い丸）につないでいきます。ドラッグで移動すると近くの端に吸着します。回転・左右反転・削除（キー: `R` / `F` / `Delete`）。
- **ボード設定**: 900×600、サブロク（1820×910）などのプリセットか任意のサイズ。はみ出した線路は赤く表示されます。
- **AIレイアウト提案**: 要望を日本語で書くと、AIが線路部品の並びを提案します。アプリ側で組み立てて「つながっていない端・ずれ・ボード外・重なり」を検査し、問題があればAIに直させます（最大4回）。
- **ログインとロール**: ユーザーごとに「管理者」「一般」のロールがあります。AIのAPI設定とユーザー管理は管理者だけができます。
- **AIの切り替え**: Claude・OpenAI・Gemini・ローカルLLM（Ollama / LM Studio / vLLM など OpenAI 互換API）から選べます。管理者が「管理」画面でプロバイダ・モデル・APIキー・接続先URLを設定し（環境変数でも可）、全員のAI提案にその設定が使われます。「一覧」ボタンで使えるモデルを取得できます。
- **新機能のお知らせ**: 画面右上のベル（🔔）に、新しい機能や管理者からのお知らせが未読数付きで届きます。開くと既読になり、「すべてのお知らせ」（`/news`）で更新履歴を見られます。
- **高架・立体交差と階層表示**: 線路ごとに高さ（地上・高架・勾配）を設定できます。勾配は前後の高さから自動で上り下りし、急勾配・段差・高さ不足の交差・下の線路に当たる橋脚を検査します。キャンバス左上で地上・勾配・高架の強調／非表示を切り替え、「断面図」で高さを横から確認できます。詳しくは下の「高架・立体交差」。
- **運転席で走る（一人称視点）**: キャンバス左上の「▶ 運転席で走る」で、作ったレイアウトの線路の上を運転席の視点で走る3Dの映像を見られます（three.js）。曲線・勾配・高架・橋脚と、道床の種類（バラスト・PC・スラブ・ワイドPC・高架橋）を反映します。選択中の部品から走り始め、「後ろから」では1/150の20m級の車両（133mm）3両が台車の位置で線路に沿って走ります。速度（縮尺の km/h）・一時停止・ポイントの進路（直進・分岐・交互・おまかせ、次のポイントだけ選ぶことも可）・運転席／後ろからの視点を切り替えられます。行き止まりでは手前で止まり、折り返せます。「録画」で映像を WebM で保存できます。走行の計算は `src/lib/drive.ts`、3Dの情景は `src/lib/driveScene.ts`。
- **確認結果と部品リスト**: 必要な線路を**メーカー品番**ごとに本数・箱数で表示します（ポイントは左右別）。線路延長も表示します。
- **保存**: ブラウザに自動保存。JSONファイルで保存・読み込みもできます。

- メーカー希望小売価格（税込）は [src/data/prices.ts](src/data/prices.ts)（公式一覧ページの掲載値）。

### 品番データベース

`src/lib/productDb.ts` が、カタログと価格表から品番ごとの1行（メーカー・品番・製品名・分類・左右・入数・中身の部品と本数・寸法・確認状況・価格・出典）を作ります。

- `GET /api/products` … JSON
- `GET /api/products?format=csv` … CSV（Excelで開けるようBOM付き）

端数線路セットやミニカーブのように、1箱に複数の部品が入っている品番は「中身」に部品ごとの本数を持ちます。

## 高架・立体交差

- 高さは「地上の線路のレール面からの高さ（mm）」です。標準の高架は KATO 50mm（橋脚No.5）、TOMIX 55mm（PC橋脚P10）。規格と出典は `src/data/piers.ts`。
- 「勾配」にした線路は、つながった勾配の線路をひとつの坂として、前後の高さの決まった線路の間を長さに比例して上り下りします（`src/lib/elevation.ts`）。勾配の上限は4%（KATOは248mmで10mm、TOMIXはS140で5mmが目安）。
- 高さの差が標準の高架の高さ（KATO 50mm・TOMIX 55mm）以上ある交差は立体交差、足りなければ「重なり（高さ不足）」になります。
- 高さ8mm以上の線路には、ジョイントごと（と長い線路の途中）に橋脚を立て、高さに合う橋脚を選んで部品リストに加えます。勾配橋脚セットのように1箱に何種類も入っている品番は、ほかの高さの不足分にも充てて箱数を数えます。
- TOMIXの鉄橋はレールが別売りなので、同じ長さのレール（S280・S140）も部品リストに入ります。鉄橋に付属する橋脚は数えていません。
- AIには高さ（`height`。0=地上、null=勾配）も出力させ、急勾配・段差・高さ不足・橋脚の干渉をフィードバックして直させます。

## 所有パーツからの提案と拡張案

1. 左の「所有パーツ」で品番と箱数を登録します（このブラウザに保存。「今の配置から追加」で配置済みの線路をまとめて登録することもできます）。
2. 右のAI欄でモードを選びます。
   - **自由に** … 部品の制限なし
   - **手持ちだけ** … 所有パーツの本数の範囲で組める案。使いすぎた案はアプリが「部品不足」としてAIに直させます
   - **拡張案** … 所有パーツを活かし、買い足しで広げる案。案ごとに追加で必要な品番・本数・箱数・費用を表示します
3. 「出す案の数」で1〜3案を同時に作れます（案ごとに方向を変えます。拡張案なら小・中・大の規模）。
4. 「自由に」と「拡張案」では、任意で**予算の上限**（円）を入れられます。追加で買う部品の合計（メーカー希望小売価格・税込、箱単位）が上限以内の案だけを出します。所有パーツの分は費用に数えません。AIには部品1本あたりの価格を渡し、上限を超えた案は「予算超過」として直させます。直しても収まらなかった案は出さず、理由を表示します。空欄なら従来どおり制限なしです。
5. 部品リストには所有パーツとの差分（不足本数）と価格も出ます。

## パターンの編集・保存

- 提案された案は「表示して編集」でキャンバスに出し、自由に編集できます。「登録」でアプリ内に保存。
- 「パターンの保存」欄で、新しく登録・上書き保存・名前変更・削除ができます（このブラウザに保存）。
- 1件ずつ、または全パターンをまとめてJSONファイルに出力でき、そのファイル（以前の「JSONで保存」で作ったファイルも）を読み込めます。
- 部品の形は `src/lib/shapes.ts` の「経路（直線と円弧の並び）」で表すので、ジョイントが3つ以上の部品（3方・交差・ダブルクロス・複線）も同じ仕組みで配置・接続判定できます。

## 仕組み

AIに座標を直接計算させるとずれが出やすいため、AIには「どの部品をどの順につなぐか」だけを構造化出力（JSON）で出させ、座標はアプリが計算します。

```
要望 ──▶ AI (Claude / OpenAI / Gemini / ローカルLLM, 構造化出力) ──▶ 部品の並び
                ▲                                 │
                └── 問題点のフィードバック ◀── 幾何計算・検査 (src/lib/plan.ts, geometry.ts)
```

| ファイル | 役割 |
|---|---|
| `src/data/trackCatalog.ts` | KATO・TOMIXの品番・寸法（公式サイトから抽出） |
| `src/lib/shapes.ts` | 部品の形（直線・円弧の経路）と、そこから求めるジョイント |
| `src/lib/parts.ts` | カタログから部品定義を生成 |
| `src/lib/bom.ts` | 品番ごとの必要本数・箱数の集計 |
| `src/lib/geometry.ts` | 配置計算、接続判定、はみ出し・重なり・立体交差・段差・勾配の検査、部品集計 |
| `src/lib/elevation.ts` | 高さ（勾配の自動計算）と橋脚の配置 |
| `src/data/piers.ts` | 高架の高さ・勾配の規格と橋脚の品番 |
| `src/lib/plan.ts` | AIの出力スキーマと、部品の並び → 配置への変換 |
| `src/lib/ai.ts` | システムプロンプトと、検証・再試行ループ（プロバイダ共通） |
| `src/lib/llm/` | プロバイダごとの呼び出し（`anthropic.ts` / `openai.ts`（ローカルLLMも） / `gemini.ts`）と設定の解決 |
| `src/lib/server/` | ユーザー・AI設定・お知らせの保存（`store.ts`）、パスワード、ログイン状態、ロールの確認（`auth.ts`）、ユーザー管理、お知らせ（`notices.ts`） |
| `src/data/releases.ts` | リリースノート（新機能のお知らせ。デプロイで自動的に出る） |
| `src/app/api/auth/`、`src/app/api/admin/` | ログイン・ログアウト・パスワード変更、ユーザー管理とAI設定（管理者だけ） |
| `src/app/api/models/route.ts` | モデル一覧API（管理者だけ） |
| `src/app/api/propose/route.ts` | 提案API |
| `src/components/Editor.tsx` | エディタ画面 |

## ログインとロール

| ロール | できること |
|---|---|
| 管理者 | レイアウトの作成・AI提案に加えて、「管理」画面でAIの設定（プロバイダ・モデル・APIキー・接続先URL）とユーザー管理（追加・ロール変更・パスワード再設定・削除） |
| 一般 | レイアウトの作成・AI提案（管理者が設定したAIを使う）・自分のパスワード変更。AIの設定は見えず、変えられない |

- 最初の管理者は、ユーザーが1人もいないときだけ `NINEGAGE_ADMIN_USER` と `NINEGAGE_ADMIN_PASSWORD`（10文字以上）から作られます。以降は「管理」画面でユーザーを追加してください。
- ユーザーとAI設定は `NINEGAGE_DATA_DIR`（既定 `./data`、Docker では `/data`）の `store.json` に保存します（権限600）。パスワードは scrypt のハッシュで、APIキーは平文で入るので、このファイルの扱いに注意してください。
- ログイン状態は署名付きの Cookie（HttpOnly、SameSite=Lax、本番は Secure）で14日間です。パスワードの変更・再設定やロールの変更で、そのユーザーのほかのログインは切れます。
- 管理者が1人もいなくなる変更（最後の管理者を一般にする・削除する）と、自分自身の削除はできません。
- ログインの失敗は、同じ送信元またはユーザー名で15分に10回までです。
- 書き換えの要求は、同じサイトの画面からだけ受け付けます（Origin を確認）。
- `http://` で試すときは `NINEGAGE_INSECURE_COOKIE=true`（`npm run dev` では不要）。

## 新機能のお知らせ

| 種類 | 登録のしかた | 出るタイミング |
|---|---|---|
| リリースノート | `src/data/releases.ts` の先頭に1件足す（id・日時・タイトル・本文・対象） | デプロイ後、`date` の日時から。管理画面での作業は不要 |
| 管理者のお知らせ | 「管理」画面の「お知らせ」で登録・編集・削除 | すぐ、または指定した公開日時から（予約） |

- 対象は「全員」か「管理者だけ」。一般ユーザーには管理者向けのお知らせは見えません。
- 既読はユーザーごとに `store.json` に保存します。ベルを開くか `/news` を開くと既読になります。そのユーザーが登録される前のお知らせは、最初から既読として扱います。
- 画面は開いている間も5分ごと（とウィンドウに戻ったとき）に新着を確認します。
- 新機能を追加するPRでは、リリースノートを1件足してください（`npm test` が id の重複や日時の書き方を検査します）。
- API: `GET /api/notices`、`POST /api/notices/read`、管理者用 `GET/POST /api/admin/notices`、`PUT/DELETE /api/admin/notices/[id]`

## AIの設定

| プロバイダ | APIキー | モデル（既定） | 接続先URL |
|---|---|---|---|
| Claude | `ANTHROPIC_API_KEY` | `ANTHROPIC_MODEL`（claude-opus-5-5） | — |
| OpenAI | `OPENAI_API_KEY` | `OPENAI_MODEL`（gpt-5） | `OPENAI_BASE_URL`（任意） |
| Gemini | `GEMINI_API_KEY` | `GEMINI_MODEL`（gemini-2.5-pro） | — |
| ローカルLLM | `LOCAL_LLM_API_KEY`（任意） | `LOCAL_LLM_MODEL`（llama3.1） | `LOCAL_LLM_BASE_URL`（http://localhost:11434/v1） |

- 管理画面の設定が環境変数より優先されます。空欄の項目は環境変数を使います。キーは管理画面にも末尾4文字しか表示しません。
- 構造化出力（JSON Schema）に対応していないローカルLLMでは、自動で「JSONだけを出力」する指示に切り替えます。小さなモデルだと線路がうまく閉じないことがあるので、14B以上を目安にしてください。
- ローカルLLMのURLは、このアプリの**サーバーから見た**アドレスです。クラウドに置いた場合、手元PCのOllamaにはそのままでは届きません。
- 接続先URLを変えられるのは管理者だけです。一般ユーザーの画面からはキーもURLも送れません。

### トークンの節約（キャッシュ）

- **プロンプトキャッシュ（Claude）**: システムプロンプト（部品カタログ・例・設計のコツ。メーカーごとに固定）にキャッシュの目印を付け、さらにリクエスト全体の自動キャッシュで、検査の指摘を受けて出し直すときにそれまでの会話を再利用します。ボード・要望・所有パーツ・予算はユーザーメッセージに入れ、システムプロンプトには入れません（入れるとキャッシュが効かなくなります）。
- 複数案を頼んだときは、1つ目の応答が始まってから（＝キャッシュが書き込まれてから）2つ目以降を送ります。同時に送るとどれもキャッシュを読めないためです。
- `ANTHROPIC_CACHE_TTL=1h` にすると、システムプロンプトのキャッシュを1時間保持します（書き込みは5分の2倍の料金）。利用が5分以上あくことが多いサーバー向けです。既定は5分。
- OpenAI と Gemini は各社の自動キャッシュに任せ、読んだ量だけを集計します。
- **結果の再利用**: 同じ人が同じ条件（AIの設定・ボード・要望・所有パーツ・予算・案の方向）で頼んだときは、AIを呼ばずに前回の案を返します。画面の「新しく作り直す」で作り直せます。保持時間は `PROPOSE_CACHE_TTL_MIN`（分、既定60、0で無効）。サーバーのメモリに置くので再起動で消えます。
- 管理画面の「AIの使用量と料金」と、サーバーログの `[ai-usage]` の行で、入力・キャッシュ読込・キャッシュ書込・出力のトークン数と料金を確認できます。

### 使用量と料金の記録

- 提案した案ごとに1件、`NINEGAGE_DATA_DIR/ai-usage.jsonl` に追記します（日時・ユーザー・機能（自由／所有パーツ／拡張案）・モデル・トークン・料金）。再起動しても残ります。
- 料金は記録したときの単価で計算して保存します。単価は `src/lib/llm/pricing.ts`（Claude の公表価格、2026年11月時点）。キャッシュ書込は入力単価の1.25倍（5分）・2倍（1時間）、読込は各モデルの読込単価です。
- Claude 以外のモデルや価格の変更は `AI_PRICING_JSON` で上書き・追加できます（例 `{"gpt-5":{"input":1.25,"output":10,"cacheRead":0.125}}`、単位は米ドル／100万トークン）。単価が分からないモデルは料金に入れず、管理画面に表示します。
- 円換算のレートは管理画面で設定します（既定 1ドル=150円、`store.json` に保存）。
- API: `GET /api/admin/ai-usage?period=this-month|last-month|30d|all`、`PUT`（`{"usdJpy":150}`）、`DELETE`（保存済みの提案結果を消す。使用記録は消さない）

## デプロイ

`output: "standalone"` でビルドするので、Docker でそのまま動きます。

```bash
docker build -t nine-gage .
docker run -p 3000:3000 -v nine-gage-data:/data --env-file .env.local nine-gage
```

AI提案は1回に1〜3分かかることがあるため、リバースプロキシのタイムアウトは300秒程度にしてください。
